# Lesson 18 — x86-32 as a second x86 world

## Mission

Transfer your x86-64 reversing method to 32-bit x86 without assuming the ABI is the same.

## What changes

Expect differences in:

- register width and register set;
- pointer size;
- stack layout;
- argument passing;
- return conventions;
- position-independent code patterns;
- available instructions and compiler choices.

## Stack arguments

A common 32-bit calling convention passes arguments on the stack. At a call site, reconstruct:

1. values prepared before the call;
2. their order;
3. stack pointer changes;
4. return value use.

Do not label arguments from push order alone without considering the convention and intervening instructions.

## Frame pointers

Classic examples often show:

```text
push ebp
mov  ebp, esp
...
leave
ret
```

Optimized code can omit this shape. Function recognition must not depend on it.

## Width discipline

Track whether an operation is:

- 8 bit;
- 16 bit;
- 32 bit.

A mistaken width can corrupt your reconstruction of integers, pointers and structures.

## Exercise

Take a small C function you already understand from an earlier lab and, where your toolchain supports it, compile a 32-bit variant. Compare argument recovery, stack use and generated control flow with x86-64.

If the student environment lacks the optional 32-bit development libraries, use compiler-generated assembly rather than changing the baseline OCI.

## Principle

**Same architecture family does not mean same ABI.**
